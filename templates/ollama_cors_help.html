Fixing CORS with Ollama

Custom-endpoint mode makes your browser call your model server directly — Bench's own backend is never involved (see Settings). For a local server like Ollama, that means the request has to clear the browser's CORS check, and Ollama's default configuration doesn't allow it. This is the single most common first failure in custom-endpoint mode, not a bug in Bench.

Why this happens

Ollama only allows cross-origin requests from 127.0.0.1 and 0.0.0.0 by default. The page you're reading Bench from right now — http://localhost:3000 — is a different origin from Ollama's own http://localhost:11434, so the browser blocks the request before it ever reaches Ollama. You'll typically see an error in Bench like "Could not reach <url> directly from the browser".

The fix: OLLAMA_ORIGINS

Ollama accepts an extra allow-list of origins via the OLLAMA_ORIGINS environment variable. Set it to the exact origin shown in your browser's address bar while using Bench (or * to allow any site — simplest for local development, but it means any website you visit can talk to your local Ollama, so prefer the exact origin if you can), then restart Ollama.

Running ollama serve yourself

Set the variable for that one command:

OLLAMA_ORIGINS=http://localhost:3000 ollama serve

macOS (Ollama app)

  1. Set the variable with launchctl: 
    launchctl setenv OLLAMA_ORIGINS "http://localhost:3000"
  2. Quit and reopen the Ollama app (from the menu bar icon) so it picks up the new value.

Linux (systemd service)

  1. Open the service's override file: 
    sudo systemctl edit ollama.service
  2. Add the variable under [Service]: 
    [Service]
Environment="OLLAMA_ORIGINS=http://localhost:3000"
  3. Save, then reload and restart: 
    sudo systemctl daemon-reload
sudo systemctl restart ollama

Windows

  1. Quit Ollama from the system tray.
  2. Open Settings (Windows 11) or Control Panel (Windows 10) and search for environment variables.
  3. Choose Edit environment variables for your account.
  4. Add a new variable named OLLAMA_ORIGINS with the value set to your Bench origin (http://localhost:3000).
  5. Click OK/Apply, then start Ollama again from the Start menu.

Verify it worked

Back in Bench, open Settings, confirm your custom endpoint's base URL and model, and click "Send test message". If it still fails, double-check that the origin you set matches what's actually in your address bar — including the port — and that you fully restarted Ollama rather than just leaving it running.

For the authoritative, up-to-date reference, see Ollama's own docs: docs.ollama.com/faq ("How can I allow additional web origins to access Ollama?" and "How do I configure Ollama server?").
